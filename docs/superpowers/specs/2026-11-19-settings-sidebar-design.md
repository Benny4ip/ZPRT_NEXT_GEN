# Дизайн: настройки с боковым меню + точечная оптимизация

Дата: 2026-11-19
Статус: утверждён (с уточнениями при планировании: режимы «Авто/Ручной» и
независимый «Игровой профиль»; меню — список разделов вместо кастомного `TabControl`)
Связанные документы: `docs/superpowers/specs/2026-11-13-release-beta-design.md`

## Зачем

Сейчас окно настроек — одна длинная прокручиваемая лента из семи блоков. Рядом
стоят ежедневные вещи (как подключаться, автозапуск) и технические (движок,
диагностика, свои пресеты). Новичок теряется, а опытному пользователю приходится
листать через пол-окна, чтобы добраться до нужного тумблера.

Цель — разложить настройки по понятным разделам, чтобы в «Основном» осталось
только то, что нужно при первом запуске, а технические вещи не мешали.

## Что выбрано

Вариант **A. Боковое меню разделов**. Рассматривались ещё:

- **B. Крупные карточки с раскрытием** — минимальные правки, но остаётся
  длинная прокрутка и та же смесь ежедневного с техническим. Отклонён.
- **C. Мастер быстрой настройки** — максимально прост для новичка, но неудобен
  для повторных заходов и требует больше всего переделок. Отклонён.

A выбран за масштабируемость: новый раздел добавляется одной строкой в меню,
разделы не мешают друг другу, а «Основное» остаётся коротким.

## Границы

**Входит:**
- новое окно настроек с левым меню и правой областью контента;
- перенос существующих блоков в разделы без изменения их логики;
- исправление несоответствия «Игрового профиля» и тонкой настройки фильтра;
- четыре точечные оптимизации (ниже).

**Не входит:**
- удаление legacy `MainViewModel` и его тестов;
- debounce записи `config.json`;
- разбиение `SettingsViewModel` на partial-файлы/сервисы;
- новые NuGet-пакеты, изменения upstream-скриптов движка.

## Разделы

Окно 900×720, минимум 780×600. Слева меню шириной 210 px, справа — прокручиваемая
область контента. Разделы:

1. **Основное**
   - два крупных взаимоисключающих режима: «Авто» и «Ручной»;
   - отдельный тумблер «Игровой профиль» с тонкой настройкой фильтра
     (в модели фильтр ортогонален режиму, поэтому не делаем его третьим
     взаимоисключающим выбором — иначе теряется сочетание «авто + игра»);
   - карточка текущего профиля: имя обхода, YouTube/Discord, худшая задержка;
   - подсказка, что происходит при выборе.
2. **Пресеты**
   - ручной выбор пресета (ComboBox, активен только в ручном режиме);
   - «Протестировать альты» / «Остановить», прогресс и статус;
   - список результатов: YouTube, Discord, пинг, действия «Использовать» и
     «Сделать автоматическим»;
   - «Мои пресеты»: список, добавить/изменить/удалить (бывший Expander).
3. **Запуск и трей**
   - «Запускать вместе с Windows»;
   - «Сворачивать в трей при закрытии»;
   - «Уменьшить анимацию».
4. **Обновления**
   - текущая версия программы и версия движка;
   - Portable: только «Проверить обновление», «Обновить программу», GitHub,
     пояснение «движок встроен»; никаких настроек движка;
   - Standard: путь к движку, «Обзор…», статус, «Обновить движок»;
   - «О программе» — кнопкой внизу меню, не отдельным разделом.
5. **Диагностика**
   - «Проверить связь», список целей YouTube/Discord;
   - «Открыть папку логов», «Скопировать лог»;
   - «Полный сброс Discord» с подтверждением.

Плашка «Чтобы применить изменения, перезапусти обход» остаётся сверху контента и
показывается в любом разделе, пока `NeedsRestart == true`.

## Как устроено

- В `SettingsViewModel` добавляется `SettingsSection` (enum) и свойство
  `SelectedSection`. Меню — стилизованный список разделов (`ListBox`, у пунктов
  `Tag` = значение enum, `SelectedValue` = `SelectedSection`). Контент —
  пять секций в одной сетке, видимость переключается `DataTrigger` по
  `SelectedSection`. Так устойчивее, чем кастомный `TabControl`, и логики в
  code-behind нет.
- Все существующие команды и свойства остаются: меняется только раскладка XAML.
  Это сохраняет текущие тесты и контракт `SettingsDependencies`.
- «Игровой профиль» и тонкая настройка:
  - `DetailedGameFilter` возвращает фактический `_gameFilter`, а не последнее
    запомненное значение. Тогда при выключенном профиле ComboBox честно
    показывает «Выключен», а не «Все».
  - `_lastDetailedFilter` больше не нужен для отображения; удаляется, если не
    используется после правки.
- «О программе» становится командой `OpenAboutCommand` (событие
  `AboutRequested`), чтобы не тащить code-behind в новую раскладку.
- Кэш автозапуска: состояние читается один раз при создании VM и после
  переключения; `Reload()` больше не запускает `schtasks`.

## Оптимизации (моё решение, включены в работу)

1. **Portable: первый запуск без зависания.**
   `PortableEngineInstaller.Extract` выполняется в `Task.Run`; на время распаковки
   показывается лёгкое стартовое окно с текстом «Готовим движок…». Окно
   закрывается, когда движок готов или произошла ошибка. Standard не затрагивается.
2. **Адаптивное ожидание в тесте альтов.**
   Вместо фиксированных 2 с после старта winws — цикл опроса статуса каждые
   200 мс до состояния `Running`, затем стабилизационная пауза 300 мс; предел —
   прежние 2 с. Если процесс упал, тест сразу помечает пресет неудачным.
   Ожидаемый эффект: полный перебор 22–25 пресетов быстрее примерно в 2–3 раза.
   Новые параметры конструктора `PresetTester` имеют значения по умолчанию,
   поэтому существующие вызовы и тесты не ломаются.
3. **Кэш автозапуска** — см. выше.
4. **Игровой профиль** — см. выше.

## Проверка

- `dotnet build src/ZprtNextGen.App` — без ошибок и предупреждений XAML.
- `dotnet test tests/ZprtNextGen.Core.Tests` — 191/191.
- `dotnet test tests/ZprtNextGen.App.Tests` — 46/46 плюс новые тесты:
  - `SelectedSection` по умолчанию — «Основное»;
  - `DetailedGameFilter` при выключенном профиле возвращает `Disabled`;
  - `PresetTester` завершает тест быстрее фиксированных 2 с на фейковом движке;
  - `Reload()` не вызывает автозапуск повторно (счётчик фейка).
- Ручная проверка: Portable и Standard, переключение всех разделов, сохранение
  настроек, «О программе», закрытие окна.

## Риски

- Стилизация `TabControl` под левое меню — самый хрупкий кусок XAML; проверяется
  сборкой и ручным запуском сразу после правки.
- Стартовое окно portable не должно перехватывать `ShutdownMode` и мешать
  `--tray`; при `--tray` окно показывается только на время распаковки.
