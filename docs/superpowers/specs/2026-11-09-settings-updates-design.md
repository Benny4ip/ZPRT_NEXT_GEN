# ZPRT_NEXT_GEN — доработка UI, настроек и обновлений

**Date:** 2026-11-09  
**Status:** Approved  
**База:** `docs/superpowers/specs/2026-11-08-zprt-next-gen-design.md`

## Intent

Пользователь попросил пять связанных доработок: живой индикатор (мерцание + кольцо-прогресс),
исправление выхода из трея, вынос настроек в отдельное окно с кнопкой-шестерёнкой,
тестирование всех альтернативных пресетов и обновления движка/программы с GitHub.

## Goals

- **G1.** Линия пульса мерцает; кольцо вокруг неё работает как индикатор прогресса:
  0% — остановлено, заполняется при подключении, 100% — успех, 50% — ошибка.
- **G2.** При ошибке показывается одно окно с понятным текстом (без каскада).
- **G3.** «Выход» из трея действительно завершает приложение и останавливает `winws`.
- **G4.** Настройки — отдельное окно, открывается кнопкой-шестерёнкой справа сверху.
  Нижняя плашка-Expander удалена. «О программе» доступно из настроек.
- **G5.** В настройках: тест всех альтов, «Проверить обновление», «Обновить запрет»,
  «Обновить программу».
- **G6.** «Обновить запрет» проверяет последний релиз upstream, при необходимости скачивает
  zip, заменяет `engine\` с бэкапом и переимпортирует пресеты.
- **G7.** «Обновить программу» проверяет релизы `Benny4ip/ZPRT_NEXT_GEN`, скачивает zip,
  после выхода подменяет `.exe` и перезапускает приложение.

## Non-goals

- Установщик/MSI, фоновая авто-проверка обновлений без действия пользователя.
- Обновление `lists`/пользовательских списков отдельно от движка.
- Замена `winws` на собственную реализацию.
- Автоматическое применение «лучшего» пресета после теста (только показ результата).

## Anti-goals

- Потеря рабочего движка при неудачном обновлении (обязателен бэкап и откат).
- Обновление затирает `settings.json` или пользовательские списки.
- Модальные окна ошибок каждую секунду / каскад окон.
- Зависание UI на время скачивания или теста пресетов.
- Тест альтов оставляет `winws` запущенным.

## Constraints

- .NET 10 WPF, без новых NuGet-пакетов; сеть — `HttpClient`, JSON — `System.Text.Json`.
- Все тексты — русский; код — английский.
- Приложение portable, запускается с правами администратора; обновление своей программы
  не может перезаписать работающий `.exe` — нужен helper-скрипт после выхода.
- GitHub может быть недоступен/отвечать 504 — ошибки показываются текстом, приложение
  продолжает работать; путь к движку можно указать вручную.
- Тесты не требуют сети, администратора и реального `winws`.

## Approaches

Единственный разумный путь для каждой части:

- **Кольцо.** Кастомный DP `Progress` (0…1) в `MeditationView`; геометрия дуги
  пересчитывается в code-behind, анимация — `DoubleAnimation` по DP. Это надёжнее, чем
  `StrokeDashArray`, и не зависит от толщины обводки.
- **Обновления.** GitHub Releases API + `HttpClient`. Движок: скачать zip во временную папку,
  распаковать, найти `bin\winws.exe`, проверить обязательные файлы, остановить движок,
  переименовать старую папку в бэкап, скопировать новую, импортировать пресеты; при ошибке —
  вернуть бэкап. Программа: скачать zip, распаковать, сгенерировать `.cmd`, который ждёт
  завершения процесса, заменяет `ZprtNextGen.exe`, запускает его и удаляет временные файлы.
- **Тест альтов.** Последовательный прогон в `Core`: старт пресета → пауза на инициализацию →
  проверка связи → стоп. Результаты — `IReadOnlyList<PresetTestResult>` через `IProgress`.
  Отмена — `CancellationToken`. UI показывает таблицу и прогресс.
- **Настройки.** Отдельное `SettingsWindow`, `DataContext` — существующий `MainViewModel`
  (он уже единственная точка состояния). Новые операции — методы/команды VM, чтобы не
  дублировать настройки и движок.

## Design

### Индикатор

- Новый `Progress` DP + `ProgressArc` (Path) поверх внутреннего кольца, золото `#FFC65C`,
  толщина 3, круглые концы.
- Переходы: `Stopped` → 0; `Connecting` → плавно к 0.85 за ~7 с; `Connected` → 1.0;
  `Error` → 0.5.
- Мерцание: дополнительный тонкий Path поверх линии с `DoubleAnimationUsingKeyFrames`
  (короткие вспышки 0 → 0.35 → 0.05 …), период ~2.5 с. При `ReduceMotion` — без анимации.
- Ошибка: `MainViewModel` хранит `ErrorMessage` и поднимает событие `ErrorRaised`;
  `MainWindow` показывает `MessageBox` один раз на эпизод.

### Трей

- `RequestExit()` ставит флаг и вызывает `Close()`.
- `OnClosing` при выходе отменяет закрытие, дожидается `ShutdownAsync(stopEngine)`,
  затем закрывает окно повторно (флаг `_shutdownCompleted`). Это гарантирует остановку
  `winws` до завершения процесса.

### Окно настроек

- В герое справа сверху — кнопка с шестерёнкой (векторная Path, без внешних ассетов).
- `SettingsWindow` (тёмная тема, заголовок через `DarkTitleBar`), секции:
  1. Движок: путь, «Обзор…», версия, игровой фильтр.
  2. Поведение: автозапуск, сворачивать в трей, уменьшить анимацию.
  3. Обновления: версии, «Проверить обновление», «Обновить запрет», «Обновить программу»,
     статус и прогресс.
  4. Проверка пресетов: «Тестировать все альты», прогресс, таблица результатов, отмена.
  5. Подвал: «О программе», «Закрыть».
- Нижняя плашка из `MainWindow.xaml` удаляется; сетка теряет четвёртую строку.

### Обновления

- `Core/Updates/GitHubReleaseClient`: `GetLatestAsync(repo)`, выбор `.zip` ассета.
- `Core/Updates/VersionComparer`: сравнение `1.10.4` / `v1.10.4` по числовым компонентам.
- `Core/Updates/EngineUpdater`: `UpdateAsync(latest, engineRoot, presetsPath, stopEngine, progress, ct)`.
- `Core/Updates/AppUpdater`: `PrepareAsync(latest, appDirectory, progress, ct)` возвращает путь
  к helper-скрипту; вызывающий завершает приложение и запускает скрипт.
- `Core/Presets/PresetTester`: прогон пресетов, `PresetTestResult` (Id, Name, Success,
  ElapsedMs, Detail).
- Версия приложения берётся из `AssemblyInformationalVersion`/`AssemblyVersion`; в csproj
  задаётся `Version` (например, `0.2.0`).

### Поток данных

1. Шестерёнка → `SettingsWindow(vm)`.
2. «Проверить обновление» → `vm.CheckUpdatesAsync()` → два запроса GitHub → текст в VM.
3. «Обновить запрет» → подтверждение → `vm.UpdateEngineAsync()` → остановка движка →
   `EngineUpdater` → перезагрузка каталога в VM (`ReloadCatalogAsync`).
4. «Обновить программу» → подтверждение → `AppUpdater.PrepareAsync` → запуск helper →
   `Application.Current.Shutdown()`.
5. «Тестировать все альты» → `vm.TestAllPresetsAsync()` → `PresetTester` →
   `PresetTestResults`/`PresetTestStatus` в VM.
